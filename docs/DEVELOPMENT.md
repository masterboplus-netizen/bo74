# DEVELOPMENT.md — Правила разработки

> Версия: 1.0

---

## 1. РАБОТА С КОДОМ

### Чтение
- Не проси скрины — используй `sed`, `grep`, `awk`.
- Большие файлы — через `parts/`.
- Контекст — `grep -n "def _save_wall_draft" file.py`.

### Правка
- Одна команда `python3 << 'PYEOF'` — один патч.
- Никогда не редактируй вручную на мобиле.
- Бэкап перед правкой: `cp file file.bak_$(date +%s)`.
- Проверка: `python -c "import ast; ast.parse(open('file').read())"`.

### Тестирование
- После правки — перезапуск.
- `pkill -9 -f "bot.py"; sleep 2; ./start_all.sh`.
- `tail -5 bot_start.log` — убедиться, что запустился.
- Проверка в Telegram.

### Коммит
- Понятное сообщение: `fix:`, `feat:`, `docs:`, `refactor:`.
- `git add -A && git commit -m "..." && git push`.
- Не коммитить `bo72.db` (в .gitignore).

---

## 2. ПРАВИЛА КОДА

1. **Никаких магических строк** — всё из `core/spec.py`.
2. **Никаких дублей** — одна функция, одно место.
3. **Ядро независимо** — `core/` не знает про Telegram.
4. **Один вход — один выход** — в `handle_measure_input`.
5. **Черновики в БД** — для восстановления.
6. **Специфичные callback** — раньше универсальных.
7. **Комментарии** — только там, где неочевидно.
8. **Печать в лог** — с `flush=True` для Replit.

---

## 3. СТРУКТУРА КОДА

### handlers/*.py
Команды, callback'и, простые сценарии.

### core/*.py
Бизнес-логика, работа с БД.

### interfaces/telegram/*.py
UI для Telegram — только показ и callback.

### modules/*.py
Старые модули (постепенно переезжают в core/).

### integrations/*.py
Внешние системы.

### analytics/*.py
Дашборды, отчёты, прогнозы.

---

## 4. РАБОТА С БД

### Миграции
- Файл `migrations/NNN_name.sql`.
- NNN — порядковый номер.
- Применяются при старте бота.
- Идемпотентные (try/except).

### Запросы
- Через `core.db.fetchone/fetchall/commit`.
- Никогда не пиши SQL в UI — только в core/.

### Транзакции
- `commit()` — для INSERT/UPDATE/DELETE.
- `fetchone/fetchall` — для SELECT.

---

## 5. РАБОТА С GIT

### Ветки
- main — продакшн.
- feature/* — новые фичи.
- fix/* — баг-фиксы.

### Коммиты
Формат: `<тип>: <что сделано>`

Типы:
- `feat:` — новая фича.
- `fix:` — баг-фикс.
- `docs:` — документация.
- `refactor:` — рефакторинг.
- `chore:` — техдолг.

### Push
- Перед push — pull.
- Конфликты — решать локально.
- Никаких force push в main.

---

## 6. ДЕПЛОЙ

### Replit
- Автодеплой при push в main.
- `./start_all.sh` — запуск всего.
- `watchdog.py` — следит за процессами.

### Бэкапы
- Ежедневно в 23:00 МСК.
- `backups/bo72_YYYYMMDD.db`.
- Пуш в GitHub.

### Логи
- `bot_start.log` — бот.
- `dashboard.log` — дашборд.
- `watchdog.log` — watchdog.
