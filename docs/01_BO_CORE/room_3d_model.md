# 3D-модель помещения — структура данных

## Для чего этот документ
ТЗ для построения 3D-модели из данных замерщика.
Замерщик вводит простое (стена напротив, 365 см) — Бо строит сложное (контур, 3D).

## Построение 2D-контура

### Принцип
Замерщик вводит **стены по часовой** от двери. Бо **соединяет** их в контур.
Юзер **не видит** контур — только цифры. Контур — для 3D.

### Входные данные
- Стена 1 (напротив): длина 365 см, угол 90°
- Стена 2 (справа): длина 280 см, угол 93.8°
- Стена 3 (у входа): длина 365 см, угол 90°
- Стена 4 (слева): длина 280 см, угол 88.2°

### Алгоритм
1. **Старт** — точка (0, 0) — левый нижний угол у двери
2. **Направление** — первая стена идёт «напротив» → по оси Y вверх
3. **Для каждой стены:**
   - Откладываем длину по текущему направлению
   - Поворачиваем на угол (90° = прямо, 93.8° = чуть влево и т.д.)
   - Получаем координаты конца стены → начала следующей
4. **Замыкание** — после 4-й стены возвращаемся в (0, 0)
5. **Проверка** — расхождение старта и финиша > 5% → переспросить

### Формула поворота

x2 = x1 + L * cos(angle)
y2 = y1 + L * sin(angle)

Где angle — накопленный угол (сумма отклонений от 90°).

### Пример (идеальный прямоугольник)

| Стена | Длина | Угол | Конец (x, y) |
|-------|-------|------|--------------|
| 1 | 365 | 90° | (0, 365) |
| 2 | 280 | 90° | (280, 365) |
| 3 | 365 | 90° | (280, 0) |
| 4 | 280 | 90° | (0, 0) Замкнулся |

Расхождение ~1 см — это норма (замерщик ошибся на 1 см).
Расхождение > 5% (18 см) — ошибка, переспросить.

## Построение 3D-модели

### Принцип
2D-контур — это «пол». Высота потолка — «выдавливание» пола вверх.
Получается «коробка» комнаты. Потом вычитаются ниши, добавляются проёмы.

### Шаги построения
1. **Пол** — 2D-контур из 4+ стен (полигон)
2. **Потолок** — тот же контур, сдвинутый вверх на высоту
3. **Стены** — 4 вертикальные плоскости (между полом и потолком)
4. **Ниши** — вырезаем из стен (сдвиг внутрь)
5. **Закругления** — заменяем прямой угол на дугу (по радиусу)
6. **Проёмы** (окна/двери) — вырезаем из стен (прямоугольные отверстия)
7. **Мебель/техника** — ставим «коробки» у стен (по offset_x и размерам)
8. **Коммуникации** — точки на стенах (по offset_x, offset_y)

### Учёт кривизны стен
- **Ровная стена** — плоская вертикальная плоскость
- **Кривая стена** (is_wavy=1) — усреднённая плоскость с отклонениями
- **Закругление** (has_rounded=1) — дуга радиуса `radius` в углу

### Учёт разной высоты
- Комната имеет среднюю высоту `height`
- Если `is_wavy=1` — у стены **3 точки** (низ/центр/верх)
- Для 3D берём **плоскость через 3 точки** (или усреднение)

### Учёт проёмов
- Окно — прямоугольное отверстие в стене
- Позиция: `offset_x` от угла, `sill_height` от пола
- Размер: `width` × `height`
- Если окно «сквозное» — учитываем `depth` (глубина откоса)

## Форматы данных для 3D

### Формат 1. JSON (для Three.js — интерактив в браузере)
Структура:
{
  "room": {
    "id": 42,
    "name": "Кухня",
    "height": 270,
    "room_type": "rough"
  },
  "contour": [
    {"x": 0, "y": 0},
    {"x": 0, "y": 365},
    {"x": 280, "y": 365},
    {"x": 280, "y": 0}
  ],
  "walls": [
    {
      "pos": "напротив",
      "length": 365,
      "angle": 90,
      "is_wavy": 0,
      "has_rounded": 0,
      "openings": []
    }
  ],
  "openings": [
    {
      "type": "window",
      "wall_pos": "напротив",
      "offset_x": 80,
      "width": 140,
      "height": 150,
      "sill_height": 90
    }
  ],
  "niches": [],
  "objects": [],
  "comms": []
}
Этот JSON — Three.js строит 3D в браузере (дашборд).

### Формат 2. OBJ (для SketchUp, Blender)
Текстовый формат — вершины, грани:
v 0 0 0
v 0 365 0
v 280 365 0
v 280 0 0
v 0 0 270
...
f 1 2 3 4
f 5 6 7 8
...
Вершины (v) — точки 3D. Грани (f) — полигоны (стены, пол, потолок).

### Формат 3. GLTF/GLB (современный, для веб)
Бинарный или JSON — стандарт для 3D в вебе.
Поддерживает материалы, текстуры, анимации.
Для дашборда — GLTF с Three.js.

### Что используем
- **Дашборд (интерактив)** — JSON → Three.js
- **Скачивание (SketchUp/Blender)** — OBJ
- **Будущее (материалы, текстуры)** — GLTF

### Скачивание из бота
- Кнопка «📥 Скачать 3D» в карточке комнаты
- Формат: OBJ (универсальный)
- Отправка: Telegram document (файл .obj)

## План внедрения

### Этап 1. Данные (БД)
- Миграция 019: room_type (черновая/чистовая/промежуточная)
- Миграция 020: openings (окна/двери) — таблица
- Проверить поля комнат (height_bottom/middle/top)

### Этап 2. Пошаговый ввод (бот)
- Тип помещения — при создании комнаты
- Высота потолка — 3 точки (низ/центр/верх) — одна на комнату
- Обход стен — по часовой от двери (стена 1→2→3→4)
- Особенности — галочки + структурированный замер
- Проёмы (окна/двери) — на какой стене, размеры
- Проверка контура — сумма стен vs периметр
- Убрать дубли (wall_pos_ x2, wall_final_*)
- Единицы — везде САНТИМЕТРЫ

### Этап 3. Построение 3D (ядро)
- core/room_contour.py — 2D-контур из стен
- core/room_3d.py — 3D из контура (OBJ + JSON)
- Функция check_contour(room_id) — проверка замыкания

### Этап 4. Отображение
- web_dashboard.py — страница /room/<id>/3d с Three.js
- Кнопка «В 3D» в карточке комнаты
- Скачивание .obj

### Этап 5. Проверки и фичи
- check_service_access — мешает ли выдвинуть
- check_cable_hose — дотягивается ли кабель
- check_removal_order — что снять первым
- UI коммуникаций и мебели (кнопка ➕)
- room_tasks_ и room_photos_ (заглушки сейчас)
