# 🏗️ АРХИТЕКТУРА ЯДРА «БО»

> **Версия:** 3.0 (Актуальная структура core/)
> **Дата:** 2026-10-25
> **Статус:** Активная разработка

## 1. ГЛАВНЫЙ ПРИНЦИП

**Ядро независимо от интерфейсов.**
Бот, Веб-сайт, Мобильное приложение — это «пульты управления». Ядро ничего не знает про Telegram или HTML. Всё общение идет через промежуточный слой — обработчики (handlers).

## 2. СЛОИ АРХИТЕКТУРЫ

1. **Интерфейсы (UI):** Telegram-бот, Web (FastAPI/React), Mobile (Flutter).
2. **Обработчики (Handlers):** Принимают сигналы от UI и вызывают функции ядра.
3. **Ядро (Core):** Бизнес-логика. Геометрия, сессии, сметы, ЭОМ, CRM. (Папка `core/`).
4. **База Данных (SQLite):** Таблицы объектов, комнат, задач, финансов.
5. **Внешние системы:** 1С, Банки, CAD/BIM.

## 3. МОДУЛИ ЯДРА (CORE)

Все модули в папке `core/` не должны импортировать библиотеки интерфейсов (например, `telegram` или `fastapi`).

### 3.1. Базовые модули
- `db.py` — обертка над SQLite (execute, fetchone, fetchall, commit).
- `spec.py` — **энциклопедия справочников**: типы объектов (квартиры, дома, бани, фасады), типы комнат, этапы ремонтов и крыш, материалы, шаги замеров, нормативы расхода.
- `sessions.py` — управление сессиями замеров (создание, активация, удаление).

### 3.2. Геометрия и Замеры
- `geometry.py` — математика: расчет координат стен, проверка замыкания контура, конвертация локальных координат в мировые.
- `model_3d.py` — сборка единой 3D-модели комнаты.
- `visualize.py` — рендер плана комнаты в PNG (вид сверху, изометрия).
- `rooms.py`, `measures.py`, `openings.py`, `niches.py`, `comms.py` — логика работы с сущностями замеров.

### 3.3. Экономика и Сметы
- `room_estimate.py` — смета одной комнаты (материалы + работы + ЭОМ + сантехника).
- `object_estimate.py` — **сводная смета объекта**: собирает сметы комнат + ЭОМ + сантехнику + отдельные работы.
- `extra_works.py` — учет внеплановых работ («доделки»).
- `materials.py`, `works.py`, `stages.py`, `economics.py` — справочники и расчеты.

### 3.4. Управление
- `objects.py`, `tasks.py`, `crm.py`, `finance.py`, `hr.py` — объекты, задачи, клиенты, деньги, персонал.

### 3.5. Инженерные системы
- `elec_panels.py`, `elec_rules.py`, `elec_routes.py` — ядро ЭОМ.
- `plumbing_panels.py` — ядро сантехники.

### 3.6. Слой бизнес-логики для Web/Mobile (`rooms_logic/`)
*Чистая логика без привязки к Telegram. Используется для API и будущего веба.*
- `walls.py`, `comm.py`, `openings.py`, `elec.py`, `floors.py`, `reports.py`.

### 3.7. Экспорт и Интеграции
- `export/json_export.py`, `export/dxf_export.py`, `export/pdf_export.py` — генерация файлов.
- `integrations/` — модули связи с 1С, банками и т.д.

## 4. ПРАВИЛА АРХИТЕКТУРЫ

1. **Чистота ядра:** В `core/` запрещено импортировать `telegram`, `flask` или `fastapi`.
2. **Один вход — один выход:** Функции ядра принимают четкие аргументы и возвращают словари или списки.
3. **Справочники:** Все тексты, коэффициенты и картинки берутся из `spec.py`.
4. **Бэкапы:** Перед миграциями БД всегда делается бэкап.
5. **Проверка синтаксиса:** После правки кода запускается `py_compile`.

**Конец архитектуры ядра.**
