# 📋 ПЛАН МИГРАЦИИ: ХЕРАБОРИНА -> SUPABASE

> **Дата:** 2026-11-02
> **Статус:** В разработке
> **Цель:** Перевести трекер с текстового файла `worklog.json` на облачную базу данных Supabase (5 таблиц). Обеспечить динамическое редактирование фаз, задач и подзадач прямо из интерфейса.

## 1. Архитектура (5 таблиц)
Все таблицы имеют префикс `worklog_`, чтобы не пересекаться с проектом «Мастербосс»:
1. `worklog_projects` (Проекты): `id`, `name`.
2. `worklog_phases` (Фазы): `id`, `project_id`, `name`, `order_num`.
3. `worklog_tasks` (Задачи): `id`, `phase_id`, `name`, `status`, `order_num`.
4. `worklog_subtasks` (Подзадачи): `id`, `task_id`, `name`, `status` (done/planned), `session_id`.
5. `worklog_sessions` (Сессии): `id`, `project_id`, `date`, `start`, `end`, `duration_min`, `events`, `screens`, `tasks_done`, `note`.

## 2. Связи (Как всё работает)
* `Dashboard`, `Календарь`, `График` **не переписываются**. Они берут данные из `window.DATA`.
* Новый слой загрузки (JS) запрашивает данные из Supabase, складывает их в `window.DATA`, и старые скрипты рисуют интерфейс.
* **Baseline** (часы за прошлый период) сохраняется в отдельной таблице или в `worklog_projects` и подтягивается в `window.DATA.baseline`.

## 3. Оптимизация (Чтобы всё летало)
* **Пагинация:** Загружаем только последние 20-30 сессий.
* **Кэширование:** Сохраняем данные в `localStorage` для мгновенной загрузки.
* **Агрегация:** Суммы за месяц считает SQL-запрос, а не браузер.
* **Индексы:** Создаем индексы на поля `date` и `project_id`.

## 4. Пошаговый план перехода (с бэкапами)
### Этап 1: Подготовка и Бэкап
1. Сделать копию `worklog.json` (локально).
2. Закоммитить текущее состояние в Git.
3. Экспортировать данные в `backup.json` (скрипт).

### Этап 2: Создание базы в Supabase
1. Пользователь дает `SUPABASE_URL` и `ANON_KEY`.
2. Выполнить SQL-скрипт в Supabase (создать 5 таблиц с префиксом `worklog_`).
3. Настроить RLS (Row Level Security) для безопасности.

### Этап 3: Миграция данных
1. Скрипт читает `backup.json`.
2. Переносит все фазы, задачи, подзадачи и сессии в Supabase.
3. Сохраняет `baseline` в отдельную запись (чтобы не потерять часы).

### Этап 4: Переделка интерфейса (JS)
1. Подключить библиотеку Supabase в `index.html`.
2. Создать `js/db_supabase.js` (функции чтения/записи).
3. Переписать `projects.js` (рисовать из базы + лоадеры).
4. Переписать `diary.js` (рисовать карточки из базы).

### Этап 5: Новый скрипт записи сессии
1. Обновить скрипт в `README.md`.
2. Скрипт должен писать в `worklog_sessions` и `worklog_subtasks` (с привязкой к фазе/задаче).

### Этап 6: Тестирование и откат
1. Проверить на телефоне: карточки, график, дашборд.
2. Если что-то сломалось — откатиться на `worklog.json` (бэкап).

## 5. Что нельзя потерять (Критично!)
* **Baseline:** Часы за прошлый период (записаны в `window.DATA.baseline`). Должны быть перенесены в базу.
* **Старые сессии:** Все карточки, которые уже есть, должны быть в `worklog_sessions`.
* **Фазы и задачи:** 19 фаз и задачи внутри них (из `projects.js`).
